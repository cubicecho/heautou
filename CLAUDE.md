# heautou

Heautou: a minimal OpenID Connect provider for self-hosted environments. A Node server runs
[oidc-provider](https://github.com/panva/node-oidc-provider) under `/oidc` and keeps everything in flat
JSON files; a React app built from the cubeui registry is the admin UI for clients and users, and the
sign-in page the provider sends browsers to.

## Run

```
cp .env.example .env    # set ISSUER_URL to the public URL + /oidc when other machines use it
npm install
npm run dev             # web on http://localhost:3000 (proxying /graphql, /oidc, /interaction), API on :8787
npm run check && npm test
npm run build && npm start   # one process on PORT (default 3000) serving dist/
docker compose up -d --build # the same, in a container, with the data in a named volume
```

`.env.example` documents `ISSUER_URL`, `PORT`, `DATA_DIR` and `TRUST_PROXY`.

## Layout

- `server/core/` config getters, `defaults.ts` groups (token lifetimes, key sizes), coded errors, preflight, `services.ts` (opens the stores and builds the provider)
- `server/store/` flat-file stores: `json-file.ts` (atomic whole-file writes), `clients.ts`, `users.ts` (scrypt password hashes), `keys.ts` (signing and cookie keys, made on first boot)
- `server/oidc/` `provider.ts` (oidc-provider config: scopes, claims, TTLs), `adapter.ts` (oidc-provider models as JSON files under `oidc/`; clients come from the client store), `interactions.ts` (login and automatic consent)
- `server/graphql/` SDL, schema, operation limits, logger; `write-schema.ts` prints `schema.graphql`
- `server/http/` `createApp(services)`, health, shutdown; `server/index.ts` only boots
- `web/src/components/` vendored cubeui and shadcn code: do not edit, reinstall with `npx shadcn@latest add @cubeui/<item>`
- `web/src/core/` typed GraphQL helper, query client, admin hooks, list helpers, extra icons
- `web/src/clients/`, `web/src/users/` the edit dialogs
- `web/src/routes/` TanStack file routes (`/`, `/clients`, `/users`, `/login/$uid`); the tree is generated by `npm run codegen`
- `tests/` mirrors `server/`; `tests/oidc/code-flow.test.ts` runs the whole authorization code flow (secret and PKCE) against a real server

## How a sign-in goes

1. An application sends the browser to `/oidc/auth`. The provider sends it to `/interaction/:uid`.
2. A login prompt is redirected to the web app's `/login/:uid`, which reads `/interaction/:uid/details` and posts the
   username and password as JSON to `/interaction/:uid/login`. The reply says where the browser goes next.
3. A consent prompt is granted on the spot: the operator added the client, so there is no consent screen.

## Not secure, on purpose

This is an MVP for a trusted network. The admin UI and its GraphQL API have no sign-in. Client secrets and the
private signing keys are stored in plain text in `DATA_DIR`; only user passwords are hashed. Anyone who can reach
the port can add a client or a user.
